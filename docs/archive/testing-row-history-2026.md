| Session tab inside Show details | SESSION-TAB-01 | **Passed (Deck) 2026-09-23 for steps 1–6, two new bugs split out** | Decided 2026-09-20 (roadmap Features, plan 62): opening Show details will show two tabs, *This answer* and *Session · N*, so the separate Session context row goes away. Nothing has been built for this yet, so there are no Deck steps to run. [Plan](planning/62-feature-session-five.md).  **Built 2026-09-20 (plan 62, section 3c); run on the Deck 2026-09-21 and failed.** Both tabs are drawn on the opened Show details panel - This answer (active) and Session · 11, the row 28 pixels tall - and pressing Show details moves the highlight to Hide details as designed. But the highlight never lands on the tabs row: walking down from Hide details goes to the knowledge-base notes block and then straight out to the preset chip in the question box, stepping over the tabs; walking back up skips them as well. So the Session tab cannot be opened and the Clear button at the end of it cannot be reached, and none of the four ways out could be tried. Two causes, both measured: the function that puts the highlight on that row is only called from below it, never from above, although the design note written above that code promises the downward way too; and once the panel settles the row sits at 766 to 795 with the question box's top edge at 600, so it is drawn off the visible area behind the box. Immediately after opening it was at 527 and visible, so the scroll position matters - both readings are in the evidence rather than only the convenient one. Filed as a three-star bug in `docs/roadmap.md`. Evidence `docs/test-evidence/plan62-main-tab-pass-2026-09-21.json`. **The cause was fixed and the walk down into the tabs re-run on the Deck 2026-09-21, and it passed** (`docs/test-evidence/plan63-SESSION-TAB-01.json`): with an existing answer on screen, walking down from Show details now reaches the notes block, then the tabs row, then (pressing Right) the Session tab opens showing its row list; walking down again enters the list on its first row. That walk stopped there — the rest of this row is still owed, and here are the steps for it. **Steps (starting from a chat with a finished answer already on screen — reopen an existing saved chat rather than asking a fresh question, to skip the pinned-chip and streaming variables entirely):** (1) Down-walk to **Show details**, press A — the label flips to **Hide details** and the panel opens. (2) Keep walking Down: **From the notes** block, then the **This answer / Session · N** tabs row (its own stop, `.bonsai-details-tabs-row`). (3) With the tabs row focused, press **Right** — the active tab must change from *This answer* to *Session · N* and the session row list must appear below it; press **Left** — it must change back to *This answer*. (4) With **Session · N** active, press **Down** — the ring must enter the row list on its first row. Keep pressing Down through every row to the last one (11 rows measured 2026-09-21; the count may differ tonight) — each row must take the ring and the list must scroll to keep it clear of the bottom dock, never covered. (5) Past the last row, Down again must reach the **Clear** button at the end of the body (`.bonsai-details-session-clear`). Press **A** — a confirm box titled *"Start the next question fresh?"* must open, with a **Clear** button and a **Cancel** button; press **B** or move to Cancel and press A — the box must close **without** clearing anything (do not press the confirm box's own Clear button; that is a real destructive action and this check only proves the box opens and cancels). (6) With the ring back in the Session tab's row list, press **B** — this must close the whole Show details panel (not just collapse the row you are on) and hand the ring back to the **Show details / Hide details** line, per `SessionContextTabBody`'s own `onCancelButton` wiring. **Run 2026-09-23, PASS on steps 1–6, moved to Done — two new bugs split out:** both tabs are reachable and Left/Right switch them; all 27 session rows and the Clear button take the ring, 100% visible; Clear's confirm box ("Start the next question fresh?") opens on pressing A. Two new focus bugs found in the same pass, filed separately on the roadmap with a fix already being built this session: the confirm box starts with the ring on the destructive Clear button rather than Cancel, and cancelling it (log only, nothing cleared) puts the ring on the tab bar with the whole details panel closed rather than back on the row list. Evidence `docs/test-evidence/plan64-SESSION-TAB-01.json` + screenshot, saved check `checks/plan64-SESSION-TAB-01-B-close.json`. **The Clear-box bug was fixed the same night (`e163d8c`); tried again 2026-09-23, COULD NOT RUN:** Claude Code's own permission check refused the rig's walk to the Clear button before any press went out, and the log shows 0 "clear" lines, so nothing was tried either way. Owed: a by-hand check by the maintainer — open Show details, the Session tab, then Clear, and confirm the ring starts on Cancel and stays on the Session tab after Cancel is pressed.
