Plan 58, phase 1: the "From the notes" block

This page draws the new block that would sit under a reply once bonsAI has used a note from its library. Nothing here is built yet. Every drawing is sized to the transcript column (412 pixels), uses the plugin's real colours, spacing and type, and quotes a real note's own words from the library on disk. Pick which drawing looks right, or say what to change.

One thing could not be read from the code: the Deck's own text font. Steam ships a font this page cannot load outside the plugin, so the type below uses the device's own system font at the plugin's real sizes and weights instead. Everything else, colour, spacing, radius, border, is copied from the stylesheet, not approximated.

1. Closed by default, before it is opened

A Strategy reply about Pikmin 2. The reply text below is wrong: it says there is a day limit. The block underneath names the real note; opening it (drawing 2) shows the note says the opposite.

412 px
Is there a day limit in Pikmin 2?
Yes, Pikmin 2 keeps the day limit from the first game. You've got a fixed number of days to gather enough treasure, so plan your caves carefully and don't waste daylight backtracking to the ship. Bring a mix of colours so hazards don't stall you, and call every Pikmin back to an Onion before the sun goes down or you'll lose them overnight.

1b. Beside drawing 1: the "no source" header, and a note that keeps its labels

A different real note, this one written by bonsAI with no wiki behind it (Deep Rock Galactic: Survivor's "Exploder" enemy). Opened here so the same drawing also proves the other thing today's block cannot do: a note written as labelled lines (Summary / Weak points / Tips) keeps those labels as separate lines instead of running together.

412 px
What's the deal with the ones that explode when they reach you?
Those are Exploders. Keep your distance rather than standing still, since they only hurt you by reaching you, and popping one early tends to clear the ones walking up behind it too.
Exploder · From bonsAI's own notes, no source ▾
Summary: Large orange glyphids that walk into you and detonate in a wide blast.
Weak points: Fragile, and the blasts chain, so one popped early clears the group behind it.
Tips: Weapons fire themselves, so it dies where you stand - keep distance and the blast lands in the swarm instead.

The three lines above are the note's exact words from data/kb/strategy_seed.json (section 120), including its own punctuation. Nothing was reworded for this page.

2. The same reply, block open

Same question, same wrong reply as drawing 1. Opening the block shows the note's own words, which say the opposite of what the reply just said. That contrast, visible instead of hidden, is the entire point of the block.

412 px
Is there a day limit in Pikmin 2?
Yes, Pikmin 2 keeps the day limit from the first game. You've got a fixed number of days to gather enough treasure, so plan your caves carefully and don't waste daylight backtracking to the ship. Bring a mix of colours so hazards don't stall you, and call every Pikmin back to an Onion before the sun goes down or you'll lose them overnight.
Starting out in Pikmin 2 · From the Pikmin wiki ▾
There is no day limit this time: the goal is ten thousand Pokos of treasure to clear the company's debt, and treasures and enemy bodies both pay. Two captains share the work, and the button that used to pause now swaps between them, so one can carry while the other fights. The day still ends at sunset, and any Pikmin not with a captain or back at the Onion is eaten when the night creatures wake, so watch the sun and call everyone in early. The colours: red for fire and the hardest hitters, yellow thrown highest and safe from electricity, blue the only ones for water, purple heavy and strong, white fast, poison-proof and able to see treasure buried underground. Bulbmin, found only in certain caves, shrug off every hazard but cannot leave with you.

The note text above is section 250, "Starting out in Pikmin 2", verbatim from data/kb/strategy_seed.json.

4. A troubleshooting reply, tip block open

Nothing running, a plain problem sentence. The tip's own words are shown, so a launch option or setting name arrives exactly as written rather than however the model chose to phrase it.

412 px
My game freezes for a few seconds right after I hit play. Is there a fix?
That's usually Proton warming up caches on the first launch after an update. Give it a minute before force-closing it, and if it keeps happening on every launch, clearing the shader cache for the game often clears it up too.
From the shared Deck tips ▾
Proton log: PROTON_LOG=1 %command% captures useful launch traces to ~/steam-*.log.

Tip text is pattern 10 in data/kb/compat_patterns.json, verbatim, including the launch-option string. Tips carry no per-item title in the data (only a shared topic tag like "proton"), which is why this header has no name before the source, unlike drawings 1 to 3.

The third option: open only when short

The maintainer's question 1 named three shapes: closed by default, open by default, or open only when the note is short. The first two are drawn above (1 and 2 are the same reply, closed then open). The third looks identical to drawing 2 when it applies, the difference is only in when it applies: the block would start open on its own for a short note like the Exploder tip in drawing 1b (three lines), and start closed for a long one like the Pikmin note in drawing 2 (five sentences). No separate drawing is needed for this option since its open state is the same box as drawing 2; only the rule for when it opens automatically differs.

My own recommendation

Closed by default, one line, the note's name and its source in the header, exactly as drawn in 1, 1b's closed cousin, 3a and 4's closed-row twin would look. The block is going to appear on every Strategy and troubleshooting reply that used a note, and an answer bubble on a 412-pixel column is already tight; opening the note is one press away, and the header line alone already tells the player a note was used and named where it came from. Reserve open-by-default for a version of this page where the maintainer wants the note's words to be unmissable even without a press, which trades a few lines of vertical room on every such reply for that guarantee.
